Understand how to mirror existing GitHub repositories on Entire.

Repo mirrors let you bring existing GitHub repositories into Entire’s AI-native development workflows, where agents, automation, and humans work with the same Git repositories.
A mirror exposes an existing GitHub repo as an Entire-backed Git remote. You use it through an entire:// URL, so standard Git commands like clone, fetch, pull, and push can talk to Entire without changing your Git tooling.
This makes mirrors a low-friction way to try Entire on real code, connect agents or automation to an Entire-backed Git remote, and evaluate Entire in an existing workflow before changing how the broader team works.
​
Why Use a Mirror?
Use a repo mirror when you want to:
Try Entire’s AI-native development workflows on an existing project, rather than creating a throwaway repo that does not reflect how your team actually works.
Give agents or scripts an Entire-backed Git remote for code that already lives in GitHub.
Evaluate Entire in a real workflow without coordinating a team-wide Git remote change. You can start with one checkout, agent, or script.
Use Entire for clone, fetch, and push workflows while keeping your current GitHub repository and permissions model in place.
​
Common Actions
With a repo mirror, you can:
Create a mirror for an existing GitHub repository.
Clone the mirror with an entire:// URL.
Set an existing local checkout’s Git remote to the mirror URL.
Push through the mirror to the upstream GitHub repository.
Restore the original GitHub remote URL if you need to switch back.
Remove a mirror when you no longer need it.
For command syntax and flags, see the CLI command reference.
​
What to Expect
Creating a mirror does not delete, move, or rewrite the GitHub repository.
Changing a local checkout’s remote only updates that checkout’s .git/config. It does not create or delete the server-side mirror.
Removing a mirror does not change local Git remotes that you already configured.

Mirror an existing GitHub repository on Entire and use it with Git.

​
Prerequisites
Before you create a mirror, make sure you have:
The Entire CLI installed. The latest version you should have installed is 0.7.3.
You have access to clone the GitHub repository you want to mirror
​
Verify the Mirror Command Is Available
entire repo mirror create --help
If the mirror command is not available, update the Entire CLI to the latest version, 0.7.3.
​
Log In
Log in with the Entire CLI:
entire login
Confirm that your login is active:
entire auth status
​
Check GitHub App Access
Before you create or push through a mirror, confirm that the Entire GitHub App can access the repository.
Open GitHub installed apps.
Find Entire.
If GitHub shows Permission updates requested, click Review request and approve the update.
Click Configure for Entire.
To choose which repositories Entire can access, under Repository access, choose All repositories or Only select repositories, then click Save.
​
Create the Mirror
Choose the GitHub repository you want to mirror.
export GH_OWNER="<owner>"
export GH_REPO="<repo>"
Create the mirror placement:
entire repo mirror create "github.com/$GH_OWNER/$GH_REPO"
This registers the mirror on Entire. It does not change any local Git checkout.
The repository can be written as owner/repo, an HTTPS GitHub URL, or an SSH GitHub URL. By default, the command waits until the initial clone is available on Entire.
The command prints the mirror URL when it succeeds:
Registered mirror <mirror-id>
  entire://aws-us-east-2.entire.io/gh/<owner>/<repo>
  cloning. ready
​
Use the Mirror With Git
To clone the mirror into a new checkout, use the URL printed by entire repo mirror create:
git clone "entire://aws-us-east-2.entire.io/gh/$GH_OWNER/$GH_REPO"
From an existing clone of the GitHub repository, point the local origin remote at the mirror:
cd "$GH_REPO"
git remote get-url origin
git remote set-url origin "entire://aws-us-east-2.entire.io/gh/$GH_OWNER/$GH_REPO"
git fetch origin
If you want to verify the mirror before changing the checkout’s primary remote, add it temporarily as another remote:
cd "$GH_REPO"
git remote add entire "entire://aws-us-east-2.entire.io/gh/$GH_OWNER/$GH_REPO"
git fetch entire
These commands only update your local .git/config. They do not create or delete the server-side mirror placement.
To restore origin to GitHub, set it back to the original GitHub URL:
git remote set-url origin "git@github.com:$GH_OWNER/$GH_REPO.git"
​
Verify Git Still Works
Run a normal Git command through the configured remote:
git fetch
git status
At this point, your local checkout is using the Entire mirror for Git operations.
​
Push Through the Mirror
Create a test branch, make a small change, then stage and commit it:
git switch -c mirror-push-test
echo "Mirror test" >> mirror-test.txt
git add mirror-test.txt
git commit -m "Test mirror push"
Push the commit through the mirror:
git push -u origin mirror-push-test
Entire forwards the push through the mirror to the upstream GitHub repository. Your GitHub write access, branch protection rules, and required checks still apply.
​
Remove the Mirror
When you no longer need a mirror, remove the server-side mirror placement:
entire repo mirror remove "github.com/$GH_OWNER/$GH_REPO"
This does not delete or rewrite the GitHub repository. It also does not change any local Git remotes you configured in .git/config.
​

Open GitHub installed apps.
Find Entire.
If GitHub shows Permission updates requested, click Review request and approve the update.
Click Configure for Entire.
To choose which repositories Entire can access, under Repository access, choose All repositories or Only select repositories, then click Save.
Refresh your Entire login:
entire auth logout
entire auth login
Retry the push after logging in again.
